# Аналитический отчет по задаче прогнозирования эффективности химических соединений

## 1. Введение

Цель работы - построить и сравнить модели машинного обучения для анализа химических соединений и прогнозирования показателей, связанных с их эффективностью против вируса гриппа.

В распоряжении имеются данные о химических соединениях. Для каждого соединения представлены числовые химические дескрипторы, а также целевые показатели:

- `IC50, mM`
- `CC50, mM`
- `SI`

Показатель `IC50` связан с противовирусной активностью соединения. Чем ниже значение IC50, тем меньшая концентрация соединения требуется для достижения эффекта.

Показатель `CC50` связан с цитотоксичностью. Чем выше значение CC50, тем большая концентрация требуется для проявления токсического эффекта.

Показатель `SI` является расчетной величиной и определяется через отношение `CC50 / IC50`. Чем выше SI, тем более перспективным может быть соединение с точки зрения баланса эффективности и безопасности.

В рамках работы решались следующие задачи:

- регрессия для `IC50`;
- регрессия для `CC50`;
- регрессия для `SI`;
- классификация `IC50 > median`;
- классификация `CC50 > median`;
- классификация `SI > median`;
- классификация `SI > 8`.

Для каждой задачи были проверены разные модели, выполнено сравнение качества, проведен подбор гиперпараметров и сделаны выводы о применимости подходов.

## 2. Описание данных

Датасет содержит около 1000 химических соединений. Большая часть признаков является числовыми химическими дескрипторами.

В качестве целевых переменных использовались:

| Целевая переменная | Смысл |
|---|---|
| `IC50, mM` | концентрация, связанная с противовирусной активностью |
| `CC50, mM` | концентрация, связанная с цитотоксичностью |
| `SI` | индекс селективности, рассчитывается как `CC50 / IC50` |

Так как `SI` рассчитывается через `IC50` и `CC50`, при построении моделей для задач, связанных с SI, важно было не допустить утечку данных. Поэтому в задачах классификации и регрессии целевые показатели `IC50`, `CC50` и `SI` исключались из признакового пространства.

## 3. Разведочный анализ данных

На этапе EDA были выполнены следующие шаги:

- проверка структуры данных;
- анализ пропущенных значений;
- анализ распределений целевых переменных;
- проверка связи между `IC50`, `CC50` и `SI`;
- анализ корреляций;
- анализ дисперсии признаков;
- анализ возможности применения логарифмического преобразования;
- PCA-анализ для оценки структуры признакового пространства.

### 3.1. Распределение целевых переменных

Распределения `IC50`, `CC50` и `SI` оказались сильно асимметричными. Для всех трех показателей характерна концентрация большого числа наблюдений около небольших значений и наличие отдельных очень больших значений.

Особенно выраженная асимметрия наблюдается у `SI`. Это связано с расчетной природой показателя: если `IC50` принимает очень маленькие значения, отношение `CC50 / IC50` может становиться очень большим.

Из-за такой структуры данных было принято решение проверять логарифмическое преобразование целевых переменных. Это позволяет уменьшить влияние экстремальных значений и сделать распределения более удобными для моделей.

### 3.2. Проверка расчетной природы SI

Была выполнена проверка утверждения о том, что `SI` рассчитывается на основе `IC50` и `CC50`.

Для этого был рассчитан показатель `SI_calculated = CC50 / IC50`.

После сравнения `SI_calculated` с исходным столбцом `SI` было видно, что точки располагаются практически на диагонали. Это подтверждает, что `SI` действительно является расчетным показателем, связанным с отношением `CC50 / IC50`.

Из этого следует важный вывод: использовать `IC50` и `CC50` как признаки при прогнозировании `SI` нельзя, так как это приведет к утечке данных.

### 3.3. Корреляционный анализ

Корреляционный анализ показал, что `IC50` и `CC50` имеют умеренную положительную связь. При этом линейная корреляция `SI` с `IC50` и `CC50` оказалась слабой.

Это объясняется тем, что `SI` является не самостоятельным линейным показателем, а отношением двух величин. Поэтому обычная корреляция не всегда хорошо отражает связь между `SI` и исходными показателями.

Также был выполнен анализ корреляций всех признаков с целевыми переменными. Это позволило оценить, есть ли отдельные признаки, напрямую связанные с целевыми показателями. Сильных одиночных признаков выявлено не было, поэтому основной акцент был сделан на моделях, способных учитывать сложные нелинейные зависимости.

### 3.4. Анализ признаков и PCA

Анализ дисперсии показал, что признаки имеют разные масштабы. Поэтому для моделей, чувствительных к масштабу признаков, использовалась стандартизация.

PCA-анализ показал, что первые компоненты объясняют существенную часть дисперсии, но для сохранения большей части информации требуется достаточно много компонент. Это говорит о том, что данные имеют многомерную структуру, и сильного сокращения признакового пространства без потери информации сделать нельзя.

В результате PCA использовался как инструмент анализа структуры данных, но для основных моделей признаки сохранялись в исходном виде после предобработки.

## 4. Подготовка данных

Для всех моделей использовался единый подход к предобработке:

- удаление технических столбцов;
- исключение целевых переменных из признаков;
- отбор только числовых признаков;
- заполнение пропущенных значений медианой;
- удаление признаков с нулевой дисперсией;
- стандартизация признаков.

Для классификационных задач использовалось разделение на обучающую и тестовую выборки с параметром `stratify=y`, чтобы сохранить соотношение классов.

Для оценки моделей использовались следующие метрики.

Для регрессии:

- `MAE`;
- `RMSE`;
- `R2`.

Для классификации:

- `accuracy`;
- `precision`;
- `recall`;
- `F1`;
- `ROC-AUC`.

Во всех классификационных задачах использовался baseline `DummyClassifier`, чтобы оценить, насколько модели превосходят простую стратегию без анализа признаков.

## 5. Регрессионные задачи

### 5.1. Регрессия IC50

Для прогнозирования `IC50` были проверены несколько моделей:

- Ridge;
- Lasso;
- KNN;
- RandomForestRegressor;
- ExtraTreesRegressor;
- GradientBoostingRegressor;
- HistGradientBoostingRegressor.

Распределение `IC50` оказалось сильно скошенным, поэтому дополнительно проверялось логарифмическое преобразование.

Лучшее качество показала модель `RandomForestRegressor`.

Ориентировочные результаты лучшей модели:

| Модель | MAE | RMSE | R2 |
|---|---:|---:|---:|
| RandomForestRegressor | около 1.14 | около 1.46 | около 0.45 |

Модель показывает умеренное качество. Она достаточно хорошо описывает основную массу наблюдений, но хуже справляется с большими значениями `IC50`. Это видно по графикам ошибок: для крупных значений модель часто занижает прогноз.

Основная причина сложности задачи связана с сильной асимметрией целевой переменной и наличием выбросов.

### 5.2. Регрессия CC50

Для прогнозирования `CC50` были использованы те же группы моделей.

Лучшее качество показала модель `ExtraTreesRegressor`.

Ориентировочные результаты лучшей модели:

| Модель | MAE | RMSE | R2 |
|---|---:|---:|---:|
| ExtraTreesRegressor | около 0.79 | около 1.10 | около 0.47 |

По качеству задача `CC50` оказалась немного стабильнее, чем задача `IC50`. Модели лучше улавливают закономерности, связанные с цитотоксичностью, чем закономерности, связанные с противовирусной активностью.

Анализ важности признаков показал, что для `CC50` существенную роль играют признаки, связанные с молекулярной структурой, массой, функциональными группами и физико-химическими характеристиками.

### 5.3. Регрессия SI

Задача прогнозирования `SI` оказалась наиболее сложной среди регрессионных задач.

Это ожидаемо, так как `SI` является расчетной величиной, зависящей от отношения `CC50 / IC50`. При этом сами `IC50` и `CC50` были исключены из признаков, чтобы избежать утечки данных.

Лучшее качество показала модель `RandomForestRegressor`.

Ориентировочные результаты лучшей модели:

| Модель | MAE | RMSE | R2 |
|---|---:|---:|---:|
| RandomForestRegressor | около 0.93 | около 1.26 | около 0.34 |

Качество ниже, чем для `IC50` и `CC50`. Модель частично улавливает закономерности, но точное прогнозирование `SI` по химическим дескрипторам остается сложной задачей.

На графиках видно, что модель лучше работает с основной массой наблюдений, но плохо предсказывает экстремально высокие значения `SI`.

## 6. Классификационные задачи

### 6.1. Классификация IC50 выше медианы

В этой задаче требовалось предсказать, превышает ли `IC50` медианное значение выборки.

Так как порогом была медиана, классы получились примерно сбалансированными.

Лучшей моделью после подбора гиперпараметров стала `ExtraTreesClassifier`.

Результаты финальной модели:

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| ExtraTreesClassifier | 0.721 | 0.693 | 0.790 | 0.738 | 0.786 |

Матрица ошибок показала:

| Показатель | Значение |
|---|---:|
| True Negative | 66 |
| False Positive | 35 |
| False Negative | 21 |
| True Positive | 79 |

Модель хорошо находит объекты с `IC50 > median`, что подтверждается recall около 0.79. При этом часть объектов ошибочно относится к положительному классу, поэтому precision ниже recall.

ROC-AUC около 0.79 показывает, что модель уверенно разделяет два класса лучше случайного классификатора.

### 6.2. Классификация CC50 выше медианы

В этой задаче требовалось предсказать, превышает ли `CC50` медианное значение выборки.

Класс `CC50 > median` можно интерпретировать как группу соединений с меньшей цитотоксичностью относительно данной выборки, так как более высокий CC50 означает, что большая концентрация требуется для проявления токсического эффекта.

Лучшее качество на тестовой выборке показала модель `HistGradientBoostingClassifier` с параметрами по умолчанию.

Результаты финальной модели:

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| HistGradientBoostingClassifier | 0.746 | 0.721 | 0.800 | 0.758 | 0.855 |

Матрица ошибок показала:

| Показатель | Значение |
|---|---:|
| True Negative | 70 |
| False Positive | 31 |
| False Negative | 20 |
| True Positive | 80 |

Модель хорошо находит соединения с `CC50 > median`. Значение ROC-AUC около 0.86 говорит о хорошем разделении классов.

Дополнительно был выполнен подбор гиперпараметров для нескольких сильных моделей. Однако на тестовой выборке GridSearch не улучшил качество. Поэтому финальной моделью была оставлена модель с параметрами по умолчанию, так как она показала лучший баланс метрик.

Задача `CC50 > median` оказалась наиболее качественно решаемой среди классификационных задач.

### 6.3. Классификация SI выше медианы

В этой задаче требовалось предсказать, превышает ли `SI` медианное значение выборки.

Так как `SI` является расчетной величиной, при обучении модели из признаков были исключены `IC50`, `CC50` и сам `SI`.

Лучшей моделью стала `KNN`.

Ориентировочные результаты финальной модели:

| Модель | Accuracy | F1 | ROC-AUC |
|---|---:|---:|---:|
| KNN | около 0.67 | около 0.67 | около 0.69 |

Матрица ошибок показала, что модель делает ошибки в обе стороны. Качество выше baseline, но заметно слабее, чем для задач `IC50 > median` и `CC50 > median`.

Это ожидаемый результат. `SI` является производной величиной от `IC50` и `CC50`, а сами эти показатели не использовались как признаки. Поэтому модель пытается восстановить информацию о селективности только по химическим дескрипторам.

Permutation importance для модели KNN не выявил одного явно доминирующего признака. Это говорит о том, что модель использует общую структуру признакового пространства.

### 6.4. Классификация SI больше 8

В этой задаче требовалось предсказать, превышает ли `SI` фиксированный порог 8.

В отличие от задач классификации относительно медианы, здесь классы оказались умеренно несбалансированными:

| Класс | Доля |
|---|---:|
| `SI <= 8` | около 0.64 |
| `SI > 8` | около 0.36 |

Baseline-модель показала accuracy около 0.64, но precision, recall и F1 были равны 0. Это означает, что baseline просто предсказывал самый частый класс и не находил ни одного соединения с `SI > 8`.

На первичном сравнении лучший результат по F1 показала модель `KNN`.

Результаты финальной модели:

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| KNN | 0.711 | 0.603 | 0.569 | 0.586 | 0.738 |

Матрица ошибок показала:

| Показатель | Значение |
|---|---:|
| True Negative | 102 |
| False Positive | 27 |
| False Negative | 31 |
| True Positive | 41 |

Модель нашла 41 из 72 объектов класса `SI > 8`. Recall составил около 0.57. Это лучше baseline, но качество остается умеренным.

ROC-AUC около 0.74 показывает, что модель разделяет классы лучше случайного классификатора, но разделение нельзя назвать сильным.

Дополнительно был выполнен подбор гиперпараметров для KNN, RandomForestClassifier и GradientBoostingClassifier. Однако после проверки на тестовой выборке качество моделей после подбора оказалось хуже, чем у KNN с параметрами по умолчанию. Поэтому финальной моделью была выбрана KNN без дополнительной настройки.

Permutation importance показал, что наиболее полезными признаками были:

- `fr_ester`;
- `EState_VSA4`;
- `SMR_VSA3`;
- `fr_NH1`;
- `fr_piperzine`;
- `BCUT2D_MRLOW`;
- `fr_Ar_N`.

Значения важности были положительными, но небольшими. Это говорит о том, что модель не опирается на один сильный признак, а использует совокупность характеристик молекулы.

## 8. Общие выводы

В ходе работы были построены модели для всех поставленных задач регрессии и классификации.

EDA показал, что целевые переменные имеют сильно асимметричные распределения и содержат выбросы. Это особенно заметно для `SI`, так как он является расчетным показателем.

Была подтверждена расчетная природа `SI`: показатель связан с отношением `CC50 / IC50`. Поэтому во всех задачах, связанных с `SI`, признаки `IC50`, `CC50` и `SI` исключались из обучающих данных, чтобы не допустить утечку.

Регрессионные задачи оказались сложнее классификационных. Модели лучше описывали основную массу значений, но хуже работали с экстремальными значениями. Особенно сложной оказалась регрессия `SI`.

Классификация относительно медианы дала более устойчивые результаты. Лучшей среди таких задач оказалась классификация `CC50 > median`, где модель `HistGradientBoostingClassifier` показала ROC-AUC около 0.86.

Задачи, связанные с `SI`, оказались сложнее. Это логично, так как `SI` отражает не отдельную активность или токсичность, а их соотношение. При этом исходные показатели `IC50` и `CC50` не использовались как признаки.

Для задачи `SI > 8` модель KNN смогла работать лучше baseline, но качество осталось умеренным. Такая модель может использоваться только как предварительный фильтр для отбора кандидатов, но не как окончательный инструмент принятия решений.

Важность признаков показала, что разные задачи опираются на разные группы химических дескрипторов. Для `IC50` заметнее признаки, связанные с функциональными группами и гетероциклами. Для `CC50` большую роль играют признаки, связанные с молекулярной массой, липофильностью и VSA/EState-дескрипторами. Для `SI > 8` важными оказались как фрагментные признаки, так и общие структурные дескрипторы.

Это говорит о том, что противовирусная активность, цитотоксичность и индекс селективности могут зависеть от разных аспектов химической структуры.

## 9. Ограничения работы и дальнейшие шаги

По результатам работы видно, что модели уже находят полезные закономерности в химических дескрипторах, но качество пока нельзя считать достаточным для самостоятельного принятия решений по отбору соединений. Особенно это касается задач, связанных с `SI`, где качество оказалось ниже, чем для `IC50` и `CC50`.

Дальнейшую работу можно продолжить в нескольких направлениях.

### 9.1. Расширить датасет

Количество объектов около 1000 ограничивает качество моделей, особенно для задач с выбросами и дисбалансом классов. Увеличение объема данных может повысить устойчивость моделей.

### 9.2. Добавить новые химические дескрипторы

Можно попробовать использовать дополнительные молекулярные признаки, например fingerprints, Morgan fingerprints или другие представления молекул.

### 9.3. Отдельно работать с выбросами

Для `IC50`, `CC50` и особенно `SI` стоит отдельно исследовать экстремальные значения. Возможные подходы: winsorization, логарифмирование, обучение отдельных моделей для разных диапазонов значений.

### 9.4. Проверить дополнительные модели

Можно дополнительно протестировать CatBoost, XGBoost и LightGBM. Эти модели часто хорошо работают с табличными данными.

### 9.5. Использовать более устойчивую валидацию

Для финальной оценки качества можно использовать повторную кросс-валидацию или несколько разбиений train/test, чтобы уменьшить зависимость от одного случайного разбиения.

### 9.6. Согласовать метрики с практической задачей

Если главная цель - не пропустить перспективные соединения, нужно делать акцент на recall для класса перспективных соединений. Если важнее уменьшить число ложных кандидатов, нужно усиливать precision.

### 9.7. Использовать модели как предварительный фильтр

Полученные модели не должны заменять химическую экспертизу и лабораторные проверки. Их разумно использовать как инструмент предварительного отбора соединений, чтобы сузить область поиска для дальнейших исследований.

## 10. Итог

В результате работы были построены и сравнены модели для всех поставленных задач.

Лучшие результаты были получены в задачах классификации `IC50 > median` и особенно `CC50 > median`. Задачи, связанные с `SI`, оказались сложнее, но модели все равно показали качество выше baseline.

Наиболее устойчивыми оказались ансамблевые модели деревьев и KNN в задачах, связанных с `SI`.

Главный практический вывод состоит в том, что химические дескрипторы действительно содержат информацию, полезную для предварительной оценки эффективности и безопасности соединений. Однако для практического применения моделей требуется дальнейшее улучшение качества, расширение данных и совместная интерпретация результатов специалистами по машинному обучению и химиками.
